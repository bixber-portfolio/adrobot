# adrobot

## 🔍 Описание:
**ADROBOT** - веб-приложение для работы с трекером [Keitaro](https://keitaro.io) через его Admin API. Умеет две вещи:

1. **Создать кампанию** по трём полям: название, гео и ID оффера. Приложение само собирает кампанию в Keitaro: домен, группа и источник трафика берутся из настроек, внутри создаются два потока.
2. **Редактировать существующую кампанию**: найти её по номеру, названию или алиасу, добавить или убрать офферы в потоке, посмотреть новое распределение долей и только потом отправить изменения в Keitaro кнопкой **Push to KT**.

Бэкенд - FastAPI + SQLAlchemy, фронтенд - React (Vite).

## 🧭 Как это работает:
 
### Создание кампании
В кампании создаются два потока, которые Keitaro проверяет по порядку:
 
| # | Поток | Что делает |
|---|-------|------------|
| 1 | `Not {гео} -> Google` | Трафик **не из выбранной страны** уходит на `https://www.google.com` |
| 2 | Офферный (`landings`) | Весь остальной трафик (нужная гео) идёт на выбранный оффер, доля 100% |
 
Алиас кампании генерируется автоматически. Если второй шаг не удался, созданная кампания архивируется, чтобы не оставалось полусобранных кампаний.
 
### Редактор кампании
- Редактируются потоки с офферами (тип `landings`) и **пустые потоки** (без офферов и без адреса, куда они ведут): в пустой поток можно добавить офферы, и после Push он станет офферным. Остальные потоки (например, редирект на сайт) показываются только для просмотра, менять их нужно в самом Keitaro.
- **Белая карточка** потока - то, что сейчас в Keitaro. **Жёлтая** - есть неотправленные правки.
- **Добавить оффер** - поиск по офферам Keitaro (запрос уходит, только когда в строке что-то введено; есть кнопка «Показать все»).
- **Удалить** - оффер помечается удалённым и может быть возвращён кнопкой **Вернуть**, пока правки не отправлены.
- **Закрепить** - закреплённый оффер сохраняет свою долю при пересчёте (если это возможно).
- **Доли** целые, в сумме всегда 100%; остаток от деления получает первый оффер.
- **Push to KT** отправляет в Keitaro только активные офферы. **Cancel** возвращает поток к тому, что было опубликовано (в Keitaro при этом ничего не уходит).
- **Fetch streams from KT** подтягивает актуальное состояние из Keitaro. Поток без локальных правок обновляется целиком, а в потоке с правками они сохраняются: новые офферы из Keitaro добавляются, удалённые в Keitaro помечаются удалёнными.
- Рядом с названием потока показывается количество кликов за сегодня.
- Выбранная кампания запоминается в браузере и открывается снова после обновления страницы.
Черновики (локальные правки) хранятся в базе приложения, поэтому не пропадают при перезапуске.

## 💡 Как начать пользоваться проектом:
 
Нужны Python 3.12+ и Node.js 20+. Бэкенд работает на порту **8090**, фронтенд - на **5173**.
 
1. **Склонировать репозиторий:**
```bash
git clone <адрес-репозитория>
cd adrobot
```
 
### Бэкенд
 
2. **Создать и активировать виртуальное окружение, установить зависимости:**
```bash
cd backend
# Для пользователей OC Windows:
python -m venv venv
source venv/Scripts/activate
# Для пользователей OC Linux/macOS:
python3 -m venv venv
source venv/bin/activate
 
pip install -r requirements.txt
```
 
3. **Создать файл `.env` на основе примера и заполнить его:**
```bash
cp .env.example .env     # на Windows: copy .env.example .env
```
Файл `.env` содержит ключи и в репозиторий не попадает (он в `.gitignore`). Откройте его и заполните:
 
| Переменная | Что это | Где взять |
|------------|---------|-----------|
| `KEITARO_URL` | Адрес вашего трекера, например `https://tracker.example.com` | Тот адрес, по которому вы открываете админку Keitaro. Без `/admin` и без слеша в конце |
| `KEITARO_API_KEY` | Ключ Admin API | Настройки вашего пользователя в админке Keitaro (если поля нет, ключ выдаёт администратор трекера). У ключа должны быть права на чтение офферов, кампаний, потоков и отчётов и на создание и изменение кампаний и потоков |
| `KEITARO_DOMAIN_ID` | Домен, на который будут создаваться новые кампании | Номер домена из раздела **Domains** (виден в таблице и в адресной строке при открытии домена) |
| `KEITARO_GROUP_ID` | Группа, в которую попадут новые кампании | Номер группы кампаний из раздела **Groups** |
| `KEITARO_TRAFFIC_SOURCE_ID` | Источник трафика новых кампаний | Номер из раздела **Traffic Sources** |
| `DATABASE_URL` | База приложения (черновики потоков) | По умолчанию SQLite-файл `adrobot.db` рядом с бэкендом, менять не обязательно. Для PostgreSQL: `postgresql+psycopg://user:password@localhost/adrobot` (потребуется установить драйвер) |
| `FRONTEND_ORIGIN` | Адрес фронтенда для CORS | По умолчанию `http://localhost:5173`. Менять, только если фронтенд открывается с другого адреса или порта |
 
Пример заполненного файла:
```bash
KEITARO_URL=https://tracker.example.com
KEITARO_API_KEY=0123456789abcdef0123456789abcdef
KEITARO_DOMAIN_ID=3
KEITARO_GROUP_ID=12
KEITARO_TRAFFIC_SOURCE_ID=7
DATABASE_URL=sqlite:///./adrobot.db
```
 
Если номера в интерфейсе найти сложно, их можно получить запросом к API (подставьте свои адрес и ключ):
```bash
curl -H "Api-Key: ВАШ_КЛЮЧ" -A "Mozilla/5.0" https://tracker.example.com/admin_api/v1/domains
curl -H "Api-Key: ВАШ_КЛЮЧ" -A "Mozilla/5.0" "https://tracker.example.com/admin_api/v1/groups?type=campaigns"
curl -H "Api-Key: ВАШ_КЛЮЧ" -A "Mozilla/5.0" https://tracker.example.com/admin_api/v1/traffic_sources
```
В каждом ответе нужно поле `id` нужной записи.
 
Если обязательная переменная не задана, приложение не запустится и в ошибке перечислит недостающие.
 
4. **Применить миграции базы данных:**
```bash
alembic upgrade head
```
 
5. **Запустить сервер:**
```bash
uvicorn app.main:app --port 8090 --reload
```
Документация API (Swagger): <http://localhost:8090/docs>
 
### Фронтенд
 
6. **В отдельном терминале установить зависимости и запустить:**
```bash
cd frontend
npm install
npm run dev
```
Приложение откроется на <http://localhost:5173>. Если бэкенд работает на другом адресе, задайте его в `frontend/.env`:
```bash
VITE_API_URL=http://localhost:8090
```

## ✅ Тесты:
```bash
cd backend
pytest
```
Тесты не обращаются к настоящему Keitaro (клиент подменяется), а БД создаётся в памяти. Файл `backend/.env` должен существовать (подойдут любые значения): приложение читает настройки при импорте. Покрыты: валидация, создание кампании, расчёт долей, состояния «опубликовано / не опубликовано», Cancel, слияние с Keitaro, Push и ошибки.
 
Для фронтенда: `npm run lint`.
 
### Демо без настоящего Keitaro
Для проверки интерфейса без боевого трекера есть эмулятор Keitaro:
```bash
cd backend
python fake_keitaro.py   # поднимает приложение на порту 8090 с тестовыми офферами и кампаниями
```
Это только для разработки, на боевых данных он не нужен.

## 🗂 Структура:
```
backend/
  app/
    routers/     # HTTP-слой: приём запросов и коды ответов
    services/    # бизнес-правила: создание кампании, доли, черновики, Push
    keitaro.py   # клиент Admin API Keitaro
    models.py    # таблицы БД (черновики потоков и офферов)
    errors.py    # понятные сообщения об ошибках валидации
  migrations/    # Alembic
  tests/
frontend/
  src/
    components/  # поиск, форма создания, редактор, карточки потоков
    api.js       # обращения к бэкенду
```
Запросы идут по цепочке: роутер → сервис → клиент Keitaro / база. Роутеры не содержат бизнес-логики, а сервисы ничего не знают про HTTP.

## 📌 Допущения и ограничения:
- Приложение рассчитано на одного пользователя, авторизации нет.
- Офферы не создаются из приложения: их ищут среди существующих в Keitaro. Ключ тестового сервера на создание оффера отвечал 403 (нет права).
- Вручную менять проценты нельзя: доли распределяются автоматически, управлять ими можно закреплением офферов.
- Колонки **Trends** и **Stats** в таблице есть, но данных пока не показывают.
- Для Keitaro нужен `action_type` у любого потока, поэтому офферный поток создаётся с действием `http`.
- Keitaro не проверяет, существует ли оффер, поэтому проверка выполняется в приложении перед созданием кампании.
- Удалённые в Keitaro кампании скрыты из поиска. Архивные кампании в Keitaro продолжают занимать своё название.
- Если кампанию удалили в Keitaro уже после того, как её открыли в редакторе, приложение об этом не сообщает: она остаётся открытой, а Push может пройти в архивную кампанию (или вернуть ошибку, если кампании больше нет). Этот сценарий в задании не описан, поэтому не реализован и не проверялся. В планах доработок: проверять состояние кампании при открытии и перед Push и блокировать правки удалённой.
- При Push в Keitaro уходит список только активных офферов. Нельзя отправить поток без офферов.
- Эндпоинты синхронные (`def`): для нагрузки небольшой внутренней утилиты этого достаточно. Список офферов запрашивается из Keitaro на каждый поиск.
- Формат Push и ответ списка кампаний проверялись на ограниченной части API Keitaro, поэтому перед боевым использованием стоит один раз прогнать их на тестовой кампании.
